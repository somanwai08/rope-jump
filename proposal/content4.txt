H3|5.1 玩家教學流程（目標：30 秒內上手）
P|工作人員口訣三步驟：**「站上腳印 → 看發光繩子 → 繩子到腳底前跳起來」**。
LI|1. 引導參與者站上腳印貼紙；工作人員先親自示範跳 2 下（身教最有效）。
LI|2. 用一句話講規則：「發光繩子轉到腳底前要跳起來，太慢就會被絆腳！」
LI|3. 開局前確認畫面上骨架完整入鏡（系統自動框位檢查），太暗／太遠依畫面提示調整。
LI|4. 前 2～3 跳由工作人員在旁喊拍（「跳！跳！」）帶節奏，參與者抓到感覺即可放手。
LI|5. 遊戲結束：引導在畫面輸入暱稱上排行榜，並掃描立牌 QR code 按讚追蹤（見 5.3）。
LI|6. 卡關或不好意思跳的參與者：邀請先看「無攝影機測試模式」的假人示範熱身，再決定上場。

H3|5.2 工作人員導覽要點：遊戲用了哪些 Google 技術
P|**一句話版（新手必背）**：「這是一款完全跑在瀏覽器裡的體感跳繩遊戲——AI 在你的瀏覽器內即時辨識你的動作，攝影機畫面從頭到尾不會離開這台電腦。」
P|**30 秒完整版（熟手導覽詞，可照唸）**：「你看到的骨架，是 Google 開源的 MediaPipe 姿態估計模型即時算出來的——它每秒 30 次從畫面裡找出你身上 33 個關鍵點。這個模型不是跑在雲端：它被編譯成 WebAssembly，直接在你的瀏覽器裡、用這台電腦的顯示晶片加速運算。所以你的畫面從頭到尾不會離開這台電腦，斷網也能玩。這就是 Web AI——瀏覽器本身就是 AI 應用平台。」
P|**技術解說對照表（供工作人員理解，不必逐字背）**：
TBLW|26::74
TBLH|技術::說明
TBL|**MediaPipe Pose Landmarker**::Google 開源 MediaPipe 框架中的姿態估計模型。每幀畫面經神經網路推論，輸出 33 個身體關鍵點（鼻、肩、肘、腕、髖、膝、踝等）的座標與可見度，約 30fps。本遊戲採 lite 版（權重約 5.8MB），兼顧速度與準確度，一般筆電即可即時運算。
TBL|**WASM＋GPU delegate**::模型編譯成 WebAssembly 在瀏覽器內執行，矩陣運算透過 WebGL／WebGPU 交給顯示晶片（GPU）加速，讓網頁擁有接近原生 App 的推論速度；不支援新 API 時自動退回舊管線或 CPU，永不開天窗。
TBL|**On-device 隱私架構**::推論 100% 在這台電腦的瀏覽器內完成：沒有 API、沒有雲端、斷網可玩。現場可開 F12 → Network 面板驗證零影像流量外送。
P|**進階話題（遇到技術背景訪客時）**：
LI|• **WebGPU**：Chrome 的新圖形與運算 API、WebGL 的後繼者，讓網頁用更現代的 GPU 管線做通用運算（含 AI）；本遊戲會自動偵測支援度並選擇最佳路徑。
LI|• **為什麼用 MediaPipe 而不是 TensorFlow.js**：MediaPipe Tasks 是 Google 官方把常用視覺模型（姿態、手部、人臉）連同前後處理打包好的方案，程式碼更少、開箱即用；底層同為瀏覽器內推論，兩者可互通。
LI|• **延伸願景**：Chrome 內建 AI（Gemini Nano）正讓網頁還能跑生成式模型——今天網頁「看得見你」，明天還能「跟你對話」。

TBLH|訪客會問::標準回答
TBL|影像有被上傳嗎？::沒有。模型在瀏覽器內推論；可開 F12 Network 面板驗證，沒有任何影像流量外送。
TBL|這是 AI 還是 if-else？::「你的身體在哪」是神經網路算的（Web AI）；跳繩規則是程式邏輯——如同自駕車「看路是 AI、導航不是」，感知與規則分工是業界常態架構。
TBL|準確度如何？偶爾偵測不到？::需全身（含腳）入鏡＋光線充足；lite 版模型在速度與準確度間取平衡，一般環境表現穩定，系統也會自動暫停防誤判。
TBL|手機可以玩嗎？::技術上可以（手機瀏覽器同樣支援 MediaPipe）；攤位版以筆電＋webcam 為主。
TBL|在哪可以玩到？::掃描立牌 QR code 可看社群與後續資訊；遊戲為開源網頁，任何筆電開瀏覽器即可執行。
H3|5.3 QR code 社群任務（掃碼 → 3 個社群連結按讚）
LI|• 現場準備：將**已內含 3 個社群連結**的 QR code 印製於立牌，放置攤位明顯處。
LI|• 流程：遊戲結束 → 參與者輸入暱稱上排行榜 → 工作人員引導掃描立牌 QR code → 口播提示「**這個 code 裡面有我們的 3 個社群連結**」→ 鼓勵逐一向各社群按讚／追蹤。
LI|• 標準話術：「幫我們按個讚，下次活動第一時間通知你！」每局結束口播一次。
LI|• 執行細節：掃碼與按讚由參與者用自己的手機操作，工作人員不代按；排隊與圍觀人潮於等待時亦可掃碼。
H3|5.4 GDG HK 是什麼（攤位常駐介紹）
LI|• **Google Developer Group（GDG）Hong Kong**：由開發者自發組成的 Google 技術社群（非 Google 官方部門），提供免費、低門檻的技術聚會。
LI|• 活動類型：DevFest 年度盛會、Study Jams 讀書會、Tech Talks、Hands-on Workshops（Android／Web／Cloud／AI 等主題）。
LI|• 加入方式：追蹤社群頁面＋透過 Meetup 報名活動；完全新手友善。
